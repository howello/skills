# 开发工作流 (Dev Workflow)

此技能定义了从任务到交付的完整工作流程。

## 核心流程

1. **计划阶段** — 收到任务后先输出书面计划，等待用户批准
2. **分解阶段** — 批准后将任务分解为可独立执行的子任务
3. **执行阶段** — 派分子 agent 并行执行，每个子 agent 在独立 worktree 中工作
4. **提交流程** — 每个子 agent 完成后自动 git commit（中文简短消息），不询问
5. **合并阶段** — 所有子任务完成后，合并分支、清理 worktree
6. **验证阶段** — 最终验证确保一切正常

## 详细步骤

### 1. 计划阶段

- 收到任务后，首先生成书面计划
- 计划内容：目标、步骤分解、涉及文件、预期变更
- 等待用户明确批准
- **不要跳过此阶段**，哪怕任务看似简单

### 2. 分解与派发

- 批准后，将任务分解为 N 个可独立执行的子任务
- 每个子任务包含：具体目标、输入、预期输出
- 为每个子任务派发一个独立的子 agent
- 每个子 agent 使用 `isolation: "worktree"` 隔离工作
- 全部使用 `run_in_background` 并行启动

### 3. 子 agent 执行

每个子 agent 在其 worktree 中：
- 读取所需的上下文文件
- 执行文件创建/修改操作
- 完成后执行 `git add` + `git commit`
- commit message 使用中文，简短描述变更
- 不询问用户，直接提交

### 4. 合并

- 等待所有后台子 agent 完成
- 依次合并每个分支到主分支
- 解决可能的冲突
- 清理 worktree

### 5. 验证与通知

- 确认所有文件正确创建/修改
- 确认无冲突残留
- 通知用户工作已完成

## 适用场景

- 涉及多个独立文件的新功能开发
- 需要并行处理的多任务场景
- 任何需要结构化工作流的开发任务

## 注意事项

- 子任务粒度要适中：太小则 worktree 开销大，太大则失去并行意义
- 每个子 agent 的任务描述必须清晰、自包含
- 子 agent 之间的文件应尽量避免重叠，减少冲突概率
- 如果任务非常简单（只改一个文件），无需拆分子 agent，直接主线完成
